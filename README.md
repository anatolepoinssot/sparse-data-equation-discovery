# Sparse-Data Equation Discovery for Coupled Neutronics–Thermal Feedback

Rediscovering the IAEA 2D PWR thermal-feedback law with SINDy, from sparse sensor observations.

**Author:** Anatole Poinssot ([poinssot.anatole@gmail.com](mailto:poinssot.anatole@gmail.com))
**Context:** Research internship (*Projet de Recherche*, PRe) — ENSTA Paris, hosted at SPEIT (SJTU Paris Elite Institute of Technology), Mar.–Jul. 2026
**Supervision:** Patrick Ciarlet (ENSTA Paris), Gong Helin (SPEIT)

## What this is

This project investigates whether the governing equations coupling neutron diffusion and temperature in a nuclear reactor transient can be **recovered from sparse sensor data alone**, without knowing their functional form in advance.

The test case is the **IAEA 2D PWR benchmark** (Bao, Zhu & Gong, *J. Comput. Phys.* 543, 2025), a quarter-core pressurized-water-reactor model coupling two-group neutron diffusion to an unsteady heat equation through a temperature-dependent diffusion coefficient:

```
D_g(x, t) = D_g^0(x) + gamma_D,g * ln( T(x, t) / T_ref ),   g = 1, 2
```

This project treats that coupling law as **unknown** and uses **SINDy** (Sparse Identification of Nonlinear Dynamics, Brunton, Proctor & Kutz, *PNAS* 2016) to rediscover it from a small number of virtual sensors.

A from-scratch Sequential Thresholded Least Squares (STLS) implementation of SINDy — no external ML libraries — exactly recovers the true logarithmic law from only **7 observed sensors, 100 time snapshots and 82 reactivity-insertion scenarios**, including when the logarithm is offered merely as one candidate among eight (polynomial + trigonometric), rather than injected as the known input variable. The identification is also assessed for robustness to measurement noise on the temperature reading (Section 8.3 of the report), where it is exact and robust outside a narrow critical noise band explained in detail.

The full write-up — physical context, methodology, results, noise-robustness study, comparison with the AI-Descartes framework (Cornelio et al., *Nat. Commun.* 2023), and a discussion of the method's current limitations and next steps — is in the PRe report (not included in this repository; ask the author for a copy).

## Current scope and main limitation

The identification shown here is a **proof of concept**: the SINDy target `D_g` is built directly from the known coupling relation (using the true temperature at sensor locations), not inferred purely from raw flux (`phi_2`) observations. This is an intentional simplification, discussed at length in the report. Removing it — reconstructing `T` from `phi_2` alone (e.g. via GEIM) and inferring `D_g` by PDE-residual minimisation rather than direct regression — is the natural next step and is **not** part of the code in this repository.


`data/processed/` and `results/` are generated by the pipeline and are not versioned here (see `.gitignore`); running the scripts below recreates them.

## How to run

### Prerequisites

```bash
pip install numpy matplotlib
# FreeFem++ must be installed and accessible as `FreeFem++` on the PATH
# (or set the FREEFEM_EXE environment variable to its full path)
```

### Step by step

```bash
# 1. Run FreeFem++ for all parameter values in config.py and parse the output
#    (slow — this is a full parametric sweep; data/raw/ already contains the
#    82-scenario dataset used in the report, so this step can be skipped)
python 1_generate_data.py

# 2. Build the training set: Y matrix (7 sensors x 100 steps x N params) + D_g targets
python 2_build_training_set.py

# 3. Run SINDy to identify D_g = f(tau), tau = ln(T/T_ref)
python 3_sindy_identification.py

# 4. Validate the recovered relation against all 20 sensors
python 4_validation.py
```

If a FreeFem++ run is interrupted (step 1), `cleanup_and_resume.py` trims the raw output files back to the last complete parameter block, after which `freefem/main_resume.edp` can continue the sweep from there.

## Data

`data/raw/` contains the sensor observations actually used to produce the results in the report: **7 of 20 virtual sensors** (seed = 42), **100 time snapshots**, over **82 of the intended 200** reactivity-insertion scenarios (`a` in [0.880, 0.896] rather than the full [0.880, 0.920] — the sweep was interrupted twice by the machine sleeping during >20h runs, and 82 values already proved sufficient for exact SINDy identification, so the remaining 118 were not pursued; see the report, Chapter 4 and Table 14).

## Key design choices

| Choice | Value | Rationale |
|---|---|---|
| Output grid | 87×87 | Reduced from the reference paper's 171×171 to cut compute time |
| Sensor layout | 4×5 regular sub-grid in [30,110] cm | Avoids the reflector and control-rod regions; covers the active core |
| Sensors (total / observed) | 20 / 7 | Sparse but representative; observed subset fixed by `RANDOM_SEED = 42` |
| Parameter range | a in [0.880, 0.920], 200 values | Physically realistic reactivity-insertion range around a = 0.9 |
| T_end / dt_out | 2 s / 0.02 s | Reduced from the reference paper's 5 s / 0.01 s -> 100 snapshots |
| SINDy library | tau, tau², …, tau⁵, sin, cos, tan | Polynomial + trigonometric candidates; no prior assumption of a logarithm |
| SINDy threshold (STLS) | 1e-3 | Enforces sparsity; identification is robust for any threshold below gamma_D = 3e-3 |
